# Agent — Ask (질문창)

> [← Backend Guide](CLAUDE.md) · 코드: `routers/agent.py` · `agent/chat.py` · `agent/tools.py` · `agent/llm.py` · `knowledge/`

Ask(`/ai` 페이지, 어느 화면에서든 오른쪽 아래 플로팅 버튼이 여는 창)가 "오늘 형3404 빈 교시 뭐
있어?" 같은 질문을 받아, LLM 이 정해진 도구를 불러 답을 만듭니다. 모델은 SQL 을 만들지 않고 읽기 전용 도구만 부릅니다.
질문에 맞는 **기억**(ksain 글에서 정리해 둔 사실)·자동 일정은 첫 차례 전에 고르되, **요약만 싣지 않고 그 출처
글의 원문으로 확인한 결과를** 싣습니다(아래 「확인 단계」).

| 파일 | 하는 일 |
| --- | --- |
| `routers/agent.py` | HTTP — `/agent/chat`(SSE) · `/models` · `/warmup` · `/status` |
| `agent/chat.py` | 질문 하나 → 답 — 요약 고르기·원문 확인, 시스템 프롬프트, 도구 호출 루프, 출처 정리 |
| `agent/tools.py` | 모델이 부르는 읽기 전용 도구 |
| `agent/llm.py` | LLM 호출 한 곳 — 모델 목록 + Chat Completions |
| `knowledge/` | ksain 글 검색(`search.py`)과 기억(`facts.py`) — [ksain.guide.md](ksain.guide.md) |

## 모델 (`agent/llm.py`)

| 모델 ID | 어디로 | 언제 보이나 |
| --- | --- | --- |
| `local:<이름>` | 데스크탑 게이트웨이 `LLM_GATEWAY_URL` | 게이트웨이에 설치된 모델 (`/gateway/models`, Ollama 를 깨우지 않음) |
| `openai:<이름>` | `OPENAI_BASE_URL` | `OPENAI_API_KEY` 가 있을 때 `OPENAI_MODELS` 에 적은 것 |

질문창에서 사용자가 고르고(기기에 남습니다), 기본값은 `AGENT_MODEL` → 로컬 기본 모델 순입니다.
분석기는 `ANALYZE_MODEL` 을 따로 봅니다.

⚠️ **OpenAI 는 이용자가 질문창에서 직접 고른 경우에만 갑니다**(`resolve()`). 기본값(`AGENT_MODEL`)이 OpenAI 를
가리켜도 로컬로 가고, **게시글 분석은 로컬만 받습니다** — `--model openai:…` 를 주면 거절합니다. 개인정보처리방침
6절이 "이용자가 고른 경우에만"·"게시글 분석은 운영자가 직접 운영하는 컴퓨터에서" 를 약속하고, 글과 첨부에는 학생
명단·연락처가 그대로 있습니다. 한때 이 가이드가 "분석은 로컬, Agent 만 OpenAI" 조합을 권했는데 그 조합은 이제
기본값으로는 못 만듭니다.

⚠️ **연결은 10초만 기다립니다**(`llm._limits`) — 답을 기다리는 240초와 따로 둡니다. 게이트웨이가 죽어 있으면 방화벽이
패킷을 버려서 연결이 거절되지 않기 때문입니다.

⚠️ **데스크탑 Ollama 는 평소 꺼져 있을 수 있습니다.** 게이트웨이(`deploy/llm-gateway/gateway.py`)가
요청이 오면 켜고 1시간 조용하면 끕니다. 꺼진 상태의 첫 답은 **1분 넘게** 걸립니다(측정 83초 —
Ollama 기동 + 7.6GB 적재). 그래서 둘이 미리 깨웁니다.

- **로그인한 사람이 사이트를 쓰면** — `main.py` 의 미들웨어가 토큰을 달고 인증을 통과한 응답마다
  `llm.nudge()` 를 부르고, 5분에 한 번 게이트웨이에 적재 요청을 보냅니다. 깨우는 요청도 유휴 1시간을
  다시 채워서, 누가 쓰는 동안은 꺼지지 않습니다. ⚠️ 안드로이드 위젯(`ClassExplorer-Android/` UA)은
  뺍니다 — 사람이 없어도 15분마다 `/home` 을 불러서 넣으면 데스크탑이 하루 종일 깹니다
- **질문창에 포커스가 가면** — 화면이 `POST /agent/warmup` 을 부르고, 기다리는 동안 그 사정을 알립니다

한때(2026-10-30, 한 시간 남짓) 상시로 띄워 두기도 했습니다 — 게이트웨이의 `GATEWAY_IDLE_SECONDS=0` 이
그 모드이고, 운영자 요청으로 1시간 + 로그인 요청으로 깨우기로 되돌렸습니다.

⚠️ **게이트웨이가 죽어 있으면 질문이 답을 못 합니다.** warmup 은 실패를 삼키므로 화면에는 입력창 옆 빨간 점
(`gateway: null`)만 남고, 질문은 연결 10초 뒤 "모델에 닿지 않습니다" 로 끝납니다(한때 240초를 "질문 읽는 중" 으로
멈춰 있었습니다). 2026-10-30 에 Windows 업데이트 재부팅 뒤 로그인 화면에 머무는 동안 그랬습니다 — 게이트웨이가
로그인 시 뜨게 돼 있었습니다.

⚠️ **Ollama 기본 컨텍스트(4096 토큰)를 넘기면 프롬프트 앞부분이 조용히 잘립니다.** 도구 명세 +
검색 결과만으로 4천을 넘어서, 답이 `finish_reason=length` 로 300자에서 끊겼습니다(`total_tokens`
가 정확히 4096). 게이트웨이가 `OLLAMA_CONTEXT_LENGTH=16384` 로 띄우고, 확인은
`curl 10.8.10.1:11434/api/ps` 의 `context_length` 로 합니다. 답이 잘리면 화면에 그렇다고 붙입니다.

⚠️ **Gemma 4 는 생각(thinking) 토큰을 먼저 씁니다.** `max_tokens` 를 짧게 주면 본문이 빈 채로
끝납니다. 로컬 모델에는 `reasoning_effort: "none"` 을 붙입니다(OpenAI 호환 경로에서 이것만
먹습니다 — `think: false` 는 `/v1` 에서 무시됩니다).

## 도구 (`agent/tools.py`)

**화면에서 볼 수 있는 것만 돌려줍니다.** class-explorer 는 로그인한 사람에게 학기 전체를
보여 주므로 다른 학생·교사 시간표와 분반 명단은 열어 두고, 화면이 본인 것만 보여 주는
시험 시간표와 개인 일정은 여기서도 본인 것만 줍니다. 새 도구도 이 경계를 지키세요.

| 도구 | 하는 일 |
| --- | --- |
| `today_info` | 오늘 날짜·교시·학기·수업 있는 날인지·교시 시각표 |
| `timetable(person, date?)` | 학생·교사 한 사람의 하루 또는 한 주 |
| `room_schedule(room, date?)` | 강의실의 교시별 수업과 빈 교시 |
| `empty_rooms(date?, periods?, building?)` | 비어 있는 강의실 (형·탐·예·창 + 네 자리) |
| `common_free(people, date?)` | 여럿이 함께 비는 교시 |
| `class_info(subject, section?)` | 분반·교사·시간·인원(질문자 분반에 `mine`), 분반을 주면 명단. 교사 이름이 오면 그 교사의 분반 |
| `find_person(query)` | 이름 일부·학번으로 후보. 사람이 없고 과목 이름이면 담당 교사(또는 "이번 학기 미개설")를 붙입니다 |
| `calendar(start?, end?, query?)` | 학사일정 + 내 개인 일정. `query` 는 제목·메모와 **대상 전공·학부 이름**에 겁니다 |
| `my_exams()` | 내 시험 시간표 (`GET /exams/me` 와 같은 함수) |
| `meal(date?)` | 급식 (`fetch_meal` 재사용 — DB 먼저) |
| `course_info(name)` | 교육과정 과목 — 학점·선수과목·설명 |
| `syllabus(subject?, query?)` | 강의계획서 — 평가·진도·시험 범위. `subject="me"` 면 내 과목 전부 (아래 「강의계획서」) |
| `search(query, since?, until?, board?)` | 학교 자료 — 기억(사실, `F12` 번호) + ksain 글(근거 발췌 `passages`) |
| `read_ksain(post_id)` | 글 하나의 본문·첨부 + 그 글에서 정리한 사실 |
| `ksain_digest(start, end?)` | 기간 안의 중요 공지와 그 기간에 걸린 필참·마감 ([ksain.guide.md](ksain.guide.md)) |

### 모델이 넘기는 값은 너그럽게 받습니다

2026-10-29 에 질문 30개를 돌려 보니 도구 호출 36번 중 **7번이 실패**했고, 7번 모두 이름을 못 알아들은
것이었습니다 — `course_info("미1")`·`("선대")`·`("미방")`·`("물실1")`, `class_info("일물2")`·`("확통")`, 그리고
교사 이름을 과목 칸에 넣은 `class_info("김효진")`. 모델은 실패를 받으면 "그런 과목은 없다" 고 답하거나, 상관없는
ksain 글로 평가 비율을 지어냈습니다. 같은 질문으로 다시 돌린 결과는 `logs.md` 에 있습니다.

| 받는 것 | 어떻게 |
| --- | --- |
| 과목 줄임말 `미1`·`선대`·`일물2`·`확통` | `services/subject_names.py` 의 `rank_names` — 같음 > 앞부분·포함 > **첫 글자부터 순서대로 든 것**. `영어2` → `영어Ⅱ` 도 (아무것도 안 맞을 때만) |
| 날짜 `내일`·`목요일`·`다음 주 월요일`·`10/30`·`11월 2일` | `_date`. 요일만 오면 오늘부터 다가오는 그 요일. ⚠️ **못 읽으면 오류**입니다 — 예전엔 조용히 오늘로 바꿔 틀린 날을 답했습니다 |
| 인자 이름 `course=`·`student=`·`keyword=` | `_ALIASES` — 도구에 없는 이름일 때만 옮깁니다. `calendar(date=…)` 는 그날 하루 |
| 도구 이름 `get_timetable`·`functions.calendar` | `canonical` |
| 인자 `"#3092"`·`["3교시"]`·`"me, 25-106"` | 숫자를 뽑고, 교시 범위(`3~5`)를 펴고, 사람 목록을 쪼갭니다 |
| 인자가 dict 로 오거나 작은따옴표 JSON | `chat._arguments`. ⚠️ 못 읽으면 빈 인자로 돌리지 않고 오류를 돌려줍니다 — 빈 인자면 `timetable()` 처럼 기본값(내 시간표)으로 도는 도구가 묻지 않은 결과를 맞는 것처럼 돌려줍니다 |

⚠️ **줄임말은 첫 글자를 묶습니다.** 묶지 않으면 "학1" 이 수학1·미적분학1·일반화학1 에 다 걸립니다. 같은 단계에서
가장 촘촘히 맞은 것만 남겨서 "일물2" 는 일반물리학2 하나, "일화" 는 일반화학1·2·일반화학실험1·2 넷입니다(정말
모호합니다). 줄임말이 이 꼴이 아니면(정보과학을 `CS` 로 부르는 것처럼) 못 찾습니다.

`calendar` 의 `query` 는 일정 제목이 검색어 **안에** 든 것도 찾습니다("종업식" → "종업"). 기간을 안 주고 걸린 게
없으면 1년 앞까지, 그래도 없으면 지난 반년을 봅니다 — 개학 무렵부터 60일만 보고 12월의 종업을 놓쳐 "등록되어
있지 않습니다" 라고 답했습니다.

### 멘토링 아카이브 (`archive`)

"미2 기출 있어?", "법과학 시험 어떻게 나와?" 에 답합니다. 학업봉사부가 모은 자료 묶음(`교과별 자료/학부/과목/과목_연도_이름(학번)_유형`)
1,258개와 학업보조 책자·전공 설명회를 `archive.db`(`knowledge/archive.py`, 만드는 건 `cli/index_archive.py`)에서 찾습니다.

- **원본은 서버에 없습니다** — 이름(과목·연도·유형)과 Drive 링크, 내용을 읽은 묶음의 글 조각뿐입니다. 파일은 Drive 권한이 있어야 열립니다
- ⚠️ **데스크탑 모델일 때만 씁니다**(`Context.local_model`, OpenAI 면 명세에서도 뺍니다). 아카이브의 "당부의 말씀" 이 본인 학업·교내
  멘토링 밖의 복제·유출을 금합니다. 운영자가 이 서비스(10명 미만)의 학업 용도로 판단해 넣었습니다
- ⚠️ **학생 이름·학번을 지웁니다**(`index_archive.scrub`) — 폴더 이름에 그대로 들어 있습니다
- 학생들이 만든 비공식 자료라서 그렇다고 밝히게 하고, 공식 일정·범위·비율은 `syllabus`·`calendar` 로 보냅니다

### 강의계획서 (`syllabus`)

"미1 실라버스 분석해서 기말고사 범위 정리해줘" 에 답할 도구입니다. 파일은 `services/syllabi.py` 가 찾고 읽습니다
(로그인한 사람에게 주는 그 파일들 — `SYLLABI_DIR`).

- **이번 학기 계획서가 아닐 때가 많습니다.** 학교가 모아 준 묶음(127개)은 수강신청용이라 2023~2026-1 것이고,
  2026-2 것은 과목마다 수업에서 따로 받습니다. 결과의 `caution` 이 학기가 다르면 답에 밝히라고 시킵니다.
  받아 둔 이번 학기 계획서는 `data/syllabi/2026-2/` 에 둡니다 — 2026-10-30 에 운영자 맥북에서 4개(미적분학1·
  Calculus 2·Forensic Science·General Earth Science)를 `cli/scan_syllabi.py` 로 골라 올렸습니다. 교사·과목명으로
  가린 뒤에는 최근 학기 것이 먼저입니다(아래 순서) — "Forensic Science 시험 일정" 이 2026-2 계획서로 답했습니다
- **평가표를 미리 뽑아 둡니다**(`assessment`, `cli/index_syllabi.py` → `syllabi/.assessments.json`). 평가 항목·비율,
  퀴즈·시험·과제 일정과 범위, 성적 규정을 파일마다 모델이 한 번 읽어 적습니다. 물을 때마다 키워드로 줄을 뽑으면
  "내 과목들 평가 비율" 이 과목당 600자에 잘리고, "다음 시험이나 퀴즈 뭐 있어?" 는 답할 길이 없었습니다.
  - ⚠️ **항목마다 원문 줄(`quote`)을 받아 파일과 대조합니다**(`supported`) — 글자가 같거나, 낱말 90% 이상이 한 구간에
    모여 있고 숫자는 전부 있어야 합니다. 비율의 숫자는 인용 안에 있어야 합니다. PDF 표는 칸이 어긋나게 뽑혀서
    글자만 맞춰 보면 Calculus 2 의 맞는 비율 4개가 전부 떨어집니다
  - ⚠️ **날짜는 코드가 셉니다**(`_schedule_item`) — 이번 학기 계획서의 주차·"10.12.~10.16." 을 실제 날짜로 바꾸고 `status`
    (지남·이번 주·앞으로)를 붙입니다
  - ⚠️ **지난 학기 계획서로 날짜를 만들지 않습니다.** 적힌 날짜도 주차도 안 옮기고 "2025-1 계획서 기준 16주차" 로만 줍니다. 한때 주차를 옮겼더니
    기말 `16주차(11-30~12-06)` 가 나갔는데 올해 기말은 17주차(12-07~12-11)였습니다. 시험은 학사일정의 공식 기간(`school_exam_period`)을
    붙이고, 주차표(`this_term.weeks`)도 안 줍니다 — 주면 모델이 직접 옮깁니다. 과목 대부분이 지난 학기 계획서라서 흔한 경우입니다
  - 수집 타이머가 10분마다 부르므로 `data/syllabi/` 에 파일을 올리면 알아서 읽힙니다(파일이 그대로면 모델을 안 부름)
  - `subject="me"` 면 한 줄씩(`_assessment_brief`) — 지난 일정은 앞으로 올 게 있으면 뺍니다
- **근거 링크는 앱 화면입니다**(`SYLLABUS_URL` → frontend `/syllabus/:id`). 파일은 로그인 헤더가 있어야 받아서 서버 주소를
  걸 수 없습니다. 내 과목 전부일 때는 **답이 그 과목을 말한 것만** 남깁니다(`weak` + `chat._named`)
- **이번 학기 날짜를 같이 줍니다**(`this_term` — `Context.term_dates`). 계획서는 "제17주 기말고사" 처럼 주차로
  적혀 있어서, 학사일정 PDF 의 "N주차 종료" 표지로 만든 주차표·지금 주차와 개학·시험·종업 날짜를 붙입니다.
  "기존 학사일정"(ksain 이 아닌 PDF·수동 일정)을 Ask 가 쓰는 자리입니다
- **내 분반의 계획서를 고릅니다.** 같은 과목이라도 교사마다 파일이 따로 있어서(물리학및실험2 는 셋) 질문자 담당
  교사 이름이 든 것 → 과목명 칸으로 맞은 것 → 영어강의 여부 → 최근 학기 순입니다
- `subject="me"` 면 내 이번 학기 과목마다 평가표 + 질문에 맞는 대목(남는 자리만큼, 최대 600자) — "내 과목들 기말고사 범위" 를 도구 한 번에
- 본문은 질문 낱말이 **많이** 든 줄과 그 앞뒤 줄을 6,000자까지 싣습니다(`excerpt`). 한국어 질문에 영어 짝을
  붙여 찾습니다(기말 → final, 평가 → grading) — 계획서 절반이 영어입니다
- 첫 호출은 파일 목록을 만드느라 몇 초 걸려서 **스레드에서** 읽고, 질문창이 열릴 때(`/agent/warmup`) 미리 만듭니다
- ⚠️ 짝짓기 함정과 PDF 를 배치 모드로 읽는 이유는 `services/syllabi.py` 머리에 있습니다. 화면(`frontend/src/lib/syllabi.ts`)은
  손으로 적은 규칙으로 따로 짝지어서, 둘이 다른 파일을 고를 수 있습니다

⚠️ **일정은 완성된 한 줄(`when`)로 넘깁니다** — `"2026-10-28(수) 15:40–16:30 · 7교시"`. 날짜·시각·
학년을 따로 주면 12B 모델이 항목 여러 개를 엇갈려 짝지었습니다(수강신청 OT 의 외국인 학생 시각을
다른 학년 줄에 붙였고, 15:40 을 "4교시" 라고 적었습니다). 시스템 프롬프트에도 교시 시각표를 넣습니다.

### 질문자 개인화 — "오늘 **내** 필참교육 있어?"

질문자의 **학년과 내국인·외국인**을 학번에서 읽고 **전공**은 계정에서 받아(`profile_of`) 시스템 프롬프트에
넣고("백재원(25-059) · 2학년 · 내국인 · 정보과학 트랙(수리정보과학부) 학생"), 일정 항목과 사실마다
`mine`(질문자 해당 여부)을 코드가 미리 붙입니다(`applies`). 모델은 "내 것" 을 물으면 `mine=true` 만 고르고
이유를 한마디 붙입니다.

- 학년: 학번 앞 두 자리 = 입학 연도, 학년도는 3월에 바뀝니다. 4년째 다니는 학생은 3학년으로 묶습니다
- 외국인: **번호 200 이상**(`26-205`). 2026-2 기준 외국인 전용 과목(한국어·TOPIK·로마숫자 과목)
  수강생 18명과 정확히 같은 18명입니다. ⚠️ `영어Ⅱ` 는 내국인 1학년도 다 들어서 로마숫자 규칙에서
  빼야 합니다 — 넣으면 85명이 외국인으로 잡힙니다. 학교가 번호 체계를 바꾸면 여기부터 확인하세요
- 전공: 본인이 고른 심화필수 전공 트랙(`User.major`, `services/majors.py`). 학번으로는 알 수 없어서 팝업으로
  묻습니다. 아직 안 골랐으면 "전공 트랙 미정" 이라고 넣고 전공으로는 거르지 않습니다
- **이름·학번과 이번 학기 수업도 싣습니다**("질문한 사람의 이번 학기 수업: 미적분학1 3분반(김훈) · …").
  ⚠️ 한동안 이름·학번을 뺐더니 "내 이름이랑 학번 뭐야?" 에 모델이 "김민준, 25-012" 를 지어냈고, 수업 목록이 없을
  때는 "내 미적분학 선생님 누구야?" 에 분반 12개를 늘어놓고 어느 반이냐고 되물었습니다. 이용자가 OpenAI 를
  고르면 이것도 바깥으로 갑니다 — 개인정보처리방침 2·6절이 그렇게 적고 있으니, 싣는 것을 바꾸면 그쪽도 고칩니다.
  학번을 연결하지 않은 계정은 아이디와 "본인 시간표·시험을 알 수 없다" 를 적습니다
- 학기 주차도 싣습니다("학기는 2026-2 11주차") — 학사일정 PDF 의 "N주차 종료" 표지에서 셉니다(`Context.term_dates`)
- 해당 판정: `target_grades`(없으면 제목의 "N학년") + `target_majors`(없으면 제목의 학부 이름 —
  `majors.mentioned`) + 제목의 내국인/외국인·국내반/국제반. 제목에서는 **학부 이름만** 봅니다 — 트랙
  이름("물리학")은 "물리 올림피아드 대비반" 같은 과목·대회 이름에도 흔합니다

날짜를 받는 도구는 **홈과 같은 규칙**으로 그날을 판정합니다(`Context.day`) — 방학·주말·
휴업일이면 수업이 없고, 대체 시간표가 있으면 그 요일 수업으로 갈아 끼웁니다. 학기 데이터는
요일 단위라 이걸 안 거치면 방학에도 "수요일 시간표" 가 나옵니다.

## 흐름 (`agent/chat.py`)

`POST /agent/chat` → 기억·일정 요약 고르기 → 출처 글 원문 읽기 → 원문으로 확인·정리(모델 한 번) → 시스템
프롬프트(오늘 날짜·날짜 기준·오늘 일정·질문자·교시표·확인한 자료) + 최근 대화 8개 + 질문 → 모델이 도구를 부르면
실행해 결과(최대 9,000자)를 돌려주기를 **최대 6번** → 답. 응답은 SSE 입니다.

### 날짜는 코드가 셉니다

체육대회 날(2026-10-29) "오늘 일정 뭐야?" 에 모델이 `calendar(query="일정")` 을 불렀고, 도구가 제목·메모에 "일정"
이 든 것만 남겨 "KSA 한마당체육대회" 가 빠지자 "특별한 일정은 없습니다" 라고 답했습니다. 사용자가 틀렸다고 하자
도구도 안 부르고 "확인해 보니 체육대회입니다" 라고 따라 했습니다. 그래서 날짜 판단을 모델에게서 덜어 냈습니다.

- **오늘 걸친 학사일정은 처음부터 싣습니다**(`tools.today_events`) — 홈이 늘 보여 주는 것과 같은 정보이고 몇 줄
  안 됩니다. 짧은 일정부터 놓습니다 — 몇 달짜리("교직원 건강검진(~11.30)")가 앞에 서면 오늘만의 일정이 묻힙니다
- **어제·내일·이번 주·다음 주·이번 달의 실제 날짜와 이번 주·다음 주의 요일별 날짜**를 줍니다(`date_anchors`,
  주는 월요일부터). 12B 모델은 목요일에 "다음 주" 를 11-03~11-09 로 잡고 요일까지 하루씩 밀어 적었고, 목요일에
  "목요일 3교시 빈 교실" 을 물었더니 금요일 날짜를 넘겼습니다. 도구도 "목요일" 을 직접 받습니다(위 표)
- `calendar` 의 `query` 에서 **"일정"·"학사일정"·"스케줄" 같은 말은 버립니다**(`_GENERIC`). 그래도 걸린 게 없으면 빈
  목록 대신 기간 안의 일정을 그대로 주고 `hint` 로 알립니다 — 빈 목록을 받은 모델은 "없다" 고 답합니다
- "언제"·마감을 묻는 질문은 기억으로 답하지 말고 `calendar` 로 확인하라고 시킵니다 — "기말고사 언제야?" 에 기억만
  보고 "엑셀 파일에 있다" 고 답했습니다. 틀렸다는 말을 들으면 따라 하지 말고 다시 확인하라는 것도 같이 적었습니다

### 기억 싣기 (`recall`)

질문(과 바로 앞 질문 — "그거 언제까지야?" 같은 이어지는 질문)으로 `knowledge.facts.find()` 가 사실을
최대 6개 고릅니다. 숨기지 않았고 아직 유효한(`valid_until` 이 안 지난) 것 중에서, 질문 낱말을 희소도
무게 기준으로 **절반 넘게 덮은 것**만 고르고, 같은 주제(`topic`)가 여럿이면 **새 글의 것 하나**만 남깁니다
— 해마다 다시 오는 공지(11월 귀가·수강 정정)는 작년 사실이 올해 사실을 흐립니다. 다른 학년·전공 이야기는
빼지 않고 뒤로 보냅니다(다른 학년·전공 걸 묻기도 합니다).

⚠️ **묻는 꼴의 말은 검색어에서 뺍니다**(`knowledge/text.py` 의 `_STOP`). "나도 들어야 해?" 의 "나도"·"들어"
처럼 사실 어디에도 없는 말은 희소도가 가장 높게 잡혀서, 덮은 비율을 깎아 맞는 사실을 떨어뜨립니다 —
"화학생물학부 면접 특강 나도 들어야 해?" 가 세 핵심어를 다 덮고도 0.47 로 떨어졌습니다.

같은 질문으로 **일정 요약**도 고릅니다(`tools.ksain_events`) — ksain 글에서 자동으로 넣은 공용 일정 중 질문
낱말에 맞는 것 최대 4개(지난 반년 ~ 1년 뒤, 안 끝난 것부터)와 그 글 번호입니다. "일정"·"스케줄" 같은 말만
있으면 고르지 않습니다.

고른 사실 한 줄은 `Context.remember` 가 만든 항목으로 `memory_line` 이 씁니다 — `search`·`read_ksain` 결과의
사실과 같은 항목이라 모양이 갈라지지 않습니다. 확인 단계에는 앞에 그 사실이 나온 글 번호(`(P1)`)를 붙여 넘깁니다.

```
기억 — ksain 글에서 정리해 둔 사실이다(괄호 안은 글 날짜·게시판·제목, 대상 학년·전공, 질문자 해당 여부). …
- [F44] 면접 노하우 특강 참석 시 자기계발 점수가 부여됩니다. (2026-10-21 · 공지사항 · 학부 공지 · 화학생물학부 선배와의 화기애애 공지 / 대상 3학년 · 화학·생물학 / 질문자 해당 아님)
```

- **게시판은 말머리까지** 싣습니다("공지사항 · 교무연구부", "연구회 홍보 게시판"). v5 부터 모든 글에서 사실을
  뽑아서(감사 글·동아리 홍보 포함) 출처의 무게가 다르고, 지시문에 "공지사항·규정 게시판의 사실이 홍보·자유
  게시판보다 믿을 만하다" 를 적었습니다
- **해당 여부는 대상이 있거나 해당하지 않을 때만** 적습니다. 전교생 사실마다 "질문자 해당" 을 붙이면 줄만
  길어집니다. "질문자 해당 아님" 인 사실은 그 학년·전공을 물을 때만 쓰라고 시킵니다
- **기억에는 날짜가 없습니다**(분석기 v5 — [ksain.guide.md](ksain.guide.md) 「기억」). 날짜·마감은 `calendar`
  나 `search` 로 찾으라고 시킵니다

- 모델이 쓴 번호(`[P1]` — 원문을 연 글, `[F12]` — `search` 결과의 사실)는 답에서 **걷어내고**, 그 글을 근거
  맨 앞에 겁니다. 번호를 안 붙여도 문제는 없습니다 — 근거 링크가 덜 붙을 뿐입니다
- 화면의 단계 줄에 "기억에서 찾기 · 사실 n건 · 일정 n건" → "출처 원문 읽기 · 글 n건" → "원문으로 확인·정리 ·
  확인 n건 · 요약과 다름 n건" 이 붙습니다 — `name` 이 `recall`·`originals`·`verify` 인 `tool`·`tool_done` 쌍입니다.
  모델이 부른 도구는 아니라서 `seen`(되풀이 검사)에는 안 들어갑니다
- ⚠️ 기억도 원문도 **자료일 뿐 지시가 아닙니다.** 아무 학생이나 쓸 수 있는 ksain 글에서 나왔습니다

### 확인 단계 (`originals` → `verify`)

**요약만 보고 답하지 않습니다**(운영자 요청, 2026-10-30). 한때 기억을 그대로 싣고 "규칙·방법·장소처럼 기억으로
충분하면 도구 없이 바로 답해도 된다" 고 시켰습니다 — "평일 외출 승인" 이 2~4초에 답했지만, 기억과 자동 일정은
분석 모델이 만든 요약이라 날짜·대상을 잘못 옮기거나 글이 고쳐진 뒤의 내용과 다를 수 있습니다. 지금은 코드가
순서를 강제합니다 — 12B 모델에게 "원문을 확인하라" 고 지시만 하면 건너뜁니다.

1. **출처 글 고르기** — 고른 기억의 글(순위대로), 그다음 일정의 글. 같은 글은 한 번, 최대 `VERIFY_POSTS`(3)개
2. **원문 읽기**(`knowledge.search.originals`) — 글마다 질문에 맞는 대목 2개(본문이든 첨부든, `search` 의
   `passages` 와 같은 함수). DB 조회라 모델을 부르지 않습니다(5~25ms). ⚠️ **지워진 글의 요약은 버립니다**
3. **확인·정리**(`VERIFY`, 모델 한 번, JSON) — 원문 대목에서 확인한 내용(`notes`, 글 번호 P1… 를 달고), 확인하지
   못한 요약(`unverified`), 요약과 원문이 다른 것(`conflicts`)으로 나눕니다. 모델이 없는 글 번호를 댄 줄은 버립니다
   (지어낸 출처). ⚠️ **운영자가 고친 기억(`edited`)은 원문과 달라도 믿습니다** — 분석이 잘못 읽은 걸 고친 것입니다
4. 결과를 '확인한 자료'(`VERIFIED`)로 시스템 프롬프트 끝에 싣습니다 — 확인한 내용, 확인 못 한 요약("사실처럼
   답하지 말고 더 찾거나 확인하지 못했다고 밝혀라"), 다른 것, 그리고 원문 대목. 답은 확인한 내용으로 하고 `[P1]`
   을 붙입니다
5. 원문을 연 글은 **걸어만 둔 근거**(`weak`)로 겁니다 — 답이 `[P1]` 로 짚거나 제목을 말했을 때만 링크로 남습니다.
   상관없는 기억이 골라져도 답 밑에 엉뚱한 링크가 안 붙습니다

- 3 이 실패하면(모델 오류·JSON 깨짐) 요약과 원문 대목을 그대로 싣고(`MEMORY`) "원문으로 확인해 답하라" 고만 합니다
- 확인 단계에서 못 연 기억(4번째 글부터)은 싣지 않습니다. 모델이 더 필요하면 `search`·`read_ksain` 으로 찾습니다
- `search` 결과의 `facts`·`summary` 도 요약입니다 — 답은 같은 결과의 `passages`(원문)나 `read_ksain` 으로 확인한
  내용으로 하라고 시킵니다
- 실제 모델(gemma4:12b, 운영 DB 사본) 측정: 확인 단계 1.3~8.4초, 데워진 상태의 답 전체 10~20초. "R&E 최종보고서
  언제까지" 는 요약 8건 → 글 3건 → 확인 4건·**요약과 다름 2건**, "외출 신청 방법" 은 확인 5건·다름 1건이었습니다.
  상관없는 기억만 골라진 질문(머신러닝 교육과정)은 확인 0건으로 끝나고 모델이 `search` 로 직접 찾았습니다

**근거 순서**: ① 답이 `[P번호]` 로 짚은 원문 글, 답이 쓴 사실의 글 ② 답에 제목이 나온 글 ③ 나머지(도구가 찾은 순). 도구는 찾은 글을 다
걸어 두는데, 검색 1등 글이 답의 근거가 아닐 때가 있습니다 — "R&E 최종보고서" 를 물었더니 답은 R&E 공지로
했는데 근거 맨 위에 KAIST HRP 공지가 걸렸습니다.

⚠️ **`calendar` 가 일정마다 거는 원문 링크는 "걸어만 둔 근거"(`Context.weak`)입니다** — ③에 넣지 않고, 답이 그
일정 제목을 말했을 때만(끝의 "(23:59까지)" 같은 괄호는 떼고 봅니다) ②로 남깁니다. 기간을 넓게 잡으면 일정 수십
개가 걸려서, "오늘 일정" 답 밑에 답과 상관없는 수강신청·SAT 링크가 붙었습니다.

⚠️ **같은 도구를 같은 값으로 되풀이하는 일이 있습니다.** "이번 주 공지" 에 `ksain_digest` 를
`start` 만 넣어(하루치 → 빈 결과) 여섯 번 불렀습니다. 같은 호출은 다시 실행하지 않고 "이미
불렀다" 를 돌려주고, 두 번 되풀이하거나 마지막 차례가 되면 **도구를 빼고** 지금까지의 결과로
답하게 합니다. `ksain_digest` 의 `end` 는 비우면 오늘까지입니다.

```
data: {"type":"start","model":"local:gemma4:12b"}
data: {"type":"tool","id":"recall","name":"recall","args":{"query":"평일에 외출하려면…"}}
data: {"type":"tool_done","id":"recall","name":"recall","ok":true,"ms":7,"summary":"사실 4건 · 일정 2건"}
data: {"type":"tool","id":"originals","name":"originals","args":{"posts":[2894,3049,2427]}}
data: {"type":"tool_done","id":"originals","name":"originals","ok":true,"ms":6,"summary":"글 3건"}
data: {"type":"tool","id":"verify","name":"verify","args":{}}
data: {"type":"tool_done","id":"verify","name":"verify","ok":true,"ms":6727,"summary":"확인 5건 · 요약과 다름 1건"}
data: {"type":"thinking","step":0}
data: {"type":"tool","id":"call_1","name":"room_schedule","args":{"room":"형3404","date":"2026-10-28"}}
data: {"type":"tool_done","id":"call_1","name":"room_schedule","ok":true,"ms":41,"summary":"수업 3개 · 빈 교시 8개"}
data: {"type":"thinking","step":1}
data: {"type":"answer","text":"…","sources":[{"title":"…","url":"https://ksain.kr/document/3092"}],"seconds":6.9}
```

화면이 "지금 무엇을 하는지" 를 그리게 이벤트를 잘게 나눴습니다. `thinking` 은 모델의 차례(step 0 은
질문을 읽는 중, 그 뒤는 도구 결과를 정리하는 중), `tool`·`tool_done` 은 도구 하나의 시작과 끝입니다.
`tool_done` 의 `summary` 는 결과 한 줄(`summarize` — "사실 2건 · 글 6건", "수업 5개 · 빈 교시 6개")이고, 실패면
`ok:false` 에 오류 문구가 들어갑니다. ⚠️ **둘은 `id` 로 짝을 짓습니다** — 한 차례에 같은 도구를
두 번 부르면 이름으로는 어느 쪽이 끝났는지 못 가립니다.

**이미지**(`images`, 최대 3장, png·jpeg·webp·gif data URL, 한 장 4MB 이하)는 **이번 질문에만**
OpenAI 호환 content 배열(`text` + `image_url`)로 싣습니다 — Ollama(gemma4 가 이미지를 읽습니다)와
OpenAI 가 같은 모양을 받습니다. 저장하지 않고, 이어 묻는 질문의 `history` 에는 화면이 "(이미지
n장 첨부)" 로만 적어 보냅니다. ⚠️ 개인정보처리방침이 이렇게 적고 있습니다 — 보관·전송을 바꾸면
`PrivacyPage` 도 같이 고치세요.
