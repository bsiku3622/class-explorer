# backend/bench_router.py Guide

> [← Backend Guide](CLAUDE.md) · [← 진입점 Guide](main.guide.md)

**ksa-bench 에만 등록되는 라우터입니다** (`backend/bench_main.py`).

## 왜 있나

ksa-bench 는 전교생에게 열 앱이라, **훑는 화면**을 없애는 것이 설계의 축입니다.

| | class-explorer | ksa-bench |
| --- | --- | --- |
| 검색 | 다중·불린·초성 | **한 번에 한 명** (후보 목록 → 하나 선택) |
| 전교생 목록 화면 | `/browse` 에 있음 | 없음 |
| 남의 누적 이수 | `GET /curriculum/progress/{stu_id}` | 없음. `GET /me/progress` 로 본인만 |
| `/admin/*` | 있음 | 등록 안 함 |
| 분반 → 명단 | 있음 | **있음** (아래 참고) |

⚠️ **분반 명단은 결국 남았습니다.** 처음에는 응답에서 뺐지만, Trade(수강 변경 탐색)가
"이 분반 수강생 중 내 분반을 받을 수 있는 사람"을 찾는 기능이라 명단 없이는 성립하지
않습니다. 그래서 **데이터는 내려가되 훑는 화면이 없다**가 현재 상태입니다.

다시 좁히려면 Trade 를 "양쪽이 등록했을 때만 맞춰 주는" 매칭 방식으로 새로 만들어야
합니다. 그때 `GET /` 에서 `students` 를 빼면 됩니다.

## 목표는 차단이 아니라 비용

학교 공식 앱(가온누리)에도 전교생 시간표 검색이 있고, 학번이 연속이라 순회하면
긁힙니다. 그러니 여기서 완전히 막는 건 의미가 없습니다 — 대신 **명단을 얻는 비용을
가온누리와 같게** 만듭니다. 한 명씩 물어봐야 하게.

작정한 사람은 어차피 못 막습니다. 문제는 재미로 훑는 수백 명이고, 그건 상한과
rate limit 으로 충분히 비쌉니다.

## 엔드포인트

### `GET /` — 학기 데이터
`GET /?year=&semester=`. 응답은 class-explorer 의 `GET /` 과 거의 같습니다 —
`students`·`student_count` 에 더해 학번 분포가 붙습니다.

**학번 분포는 줍니다** — 분반마다 `year_counts`, 과목마다 `subject_year_counts`
(분반 합이 아니라 중복을 뺀 값). 분포만으로는 "누군가 재수강 중"까지만 드러나고 그게
누구인지는 여전히 한 명씩 찾아야 하므로, 이 앱이 그은 선은 **이름이 나가지 않는다**입니다.

명단을 안 보내므로 `Student` 까지 조인하지 않고 `Enrollment.stuId` 만 씁니다.

### `GET /students/search?q=` — 후보 목록
이름·학번 부분 일치. **`{stuId, name}` 만** 돌려주고 시간표는 없습니다.

| | 값 | 이유 |
| --- | --- | --- |
| 최소 글자 수 | `SEARCH_MIN_LENGTH = 2` | `김` 한 글자로 김씨 전원이 나오면 다중 검색을 없앤 의미가 사라집니다 |
| 결과 상한 | `SEARCH_LIMIT = 20` | 넘으면 `has_more: true` — 프론트가 "더 구체적으로" 를 띄웁니다 |

**초성 검색은 없습니다.** `ㄱㅊㅅ` 로 수십 명이 한 번에 걸리는 데다 어차피 상한에
잘려 쓸모도 없습니다. class-explorer 의 `searchEngine.ts` 에는 그대로 있습니다.

### `GET /students/{stu_id}` — 한 명의 시간표
해당 학기 수업 목록(과목·분반·교사·강의실·시간·학점). **한 번에 한 명만** 됩니다.

여러 명을 한 요청으로 받지 않는 것이 이 앱의 핵심 제약입니다. 학번이 연속이라
`25-001+25-002+…` 같은 다중 질의를 허용하면 한 방에 전교생이 긁힙니다.

### `GET /me/progress` — 본인 누적 이수
`curriculum_router.fetch_progress()` 를 본인 학번으로 부릅니다. 학번 미등록이면 409.

### `GET·POST /friends`, `DELETE /friends/{stu_id}` — 친구
**단방향입니다.** 내가 추가하면 끝이고 상대의 수락이 없습니다. 남의 시간표는 어차피
`GET /students/{stu_id}` 로 한 명씩 볼 수 있으니, 이 목록은 새로 뭘 열어 주는 게
아니라 자주 보는 사람을 북마크해 두는 것입니다. 승인 절차를 붙이면 마찰만 늘고
막아 주는 건 없습니다.

### `GET /friends/busy` — 친구들의 수업 시간대
친구(+본인)마다 `busy: ["MON-3", …]` 만 돌려줍니다. **무슨 수업인지는 보내지 않습니다** —
공강을 맞추는 데 필요 없고, 과목까지 주면 "누가 뭘 듣는지" 훑는 화면이 됩니다.

## Rate limit

**IP 가 아니라 계정 단위입니다.** 로그인이 필수라 계정이 더 정확하고, 같은 학교
네트워크를 IP 로 묶으면 애먼 사람이 막힙니다.

| 버킷 | 한도 | 대상 |
| --- | --- | --- |
| `search` | 40 / 60초 | 타이핑 중에도 불리므로 넉넉하게 |
| `detail` | 30 / 60초 | 실제로 시간표가 나가는 쪽 |

전교생이 700명 남짓이니 상세 30회/분이면 전원을 훑는 데 20분이 넘습니다. 사람이 손으로
하는 조회는 여기 안 걸립니다.

메모리 정리는 `_maybe_cleanup()` 이 5분마다 합니다 — `auth_router` 의 로그인 제한과
같은 방식입니다.

  캐시에 남습니다
- 새 엔드포인트가 남의 데이터를 돌려줄 수 있으면 `bench_main.py` 가 아니라
  `main.py` 에 붙일 것을 먼저 검토하세요
