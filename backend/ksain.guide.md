# ksain 수집 · 분석 · 학사일정 자동 관리 · 검색 · 기억

> [← Backend Guide](CLAUDE.md) · 코드: `backend/ksain/` · `backend/knowledge/`

ksain(가온누리) 게시글을 전부 받아 `backend/ksain.db` 에 쌓고, LLM 으로 요약·중요도·일정·사실을
뽑아 공용 학사일정과 기억(`facts`)에 반영합니다. Ask(질문창)가 같은 글을 검색하고, 기억을 시스템
프롬프트에 싣습니다.

```
ksain (api.ksain.kr 본문·첨부 / api.ksain.net 최신 목록)
   │  systemd timer, 07~23시 10분마다 (deploy/class-explorer-ksain.timer)
   ▼
ksain/sync.py ──► ksain.db (posts · attachments · gaps · state · analyses)
   │        └──► knowledge/index.py ──► ksain.db (검색 색인 — 바뀐 글만)
   ▼  밀린 글만, 최신순 150건 · 40분까지 — 데스크탑에 닿지 않으면 다음 주기로
ksain/analyze.py ──► agent/llm.py ──► 데스크탑 게이트웨이(10.8.10.1:11434) 또는 OpenAI
   │
   ▼  글마다 본 DB 에 한 번 커밋
ksain/apply.py ──────► calendar_events (source='ksain', source_ref='<글 번호>:<순번>')
knowledge/facts.py ──► facts (기억 — 글 번호에 묶인 사실)
```

**DB 가 둘입니다.** 글·첨부·분석·검색 색인은 다시 받고 다시 만들 수 있어서 ksain.db 에, 사람이 보고
고치는 결과물(자동 일정·기억)은 본 DB 에 둡니다 — 이유는 [core/db.guide.md](core/db.guide.md).

## ksain 은 한 DB 를 두 사이트가 씁니다

구 사이트(ksain.net)에서 쓴 글은 **3천 번대**, 새 사이트(ksain.kr)에서 쓴 글은
**100000번대** 번호를 받고 둘 다 `api.ksain.kr/document/get/{id}` 로 읽힙니다. 학교 공지는
지금도 구 경로로 올라오고, 학생회 글은 새 경로로 올라옵니다.

| 용도 | 주소 | 인증 |
| --- | --- | --- |
| 글 하나 | `GET api.ksain.kr/document/get/{id}` | 없음 |
| 첨부 | `GET api.ksain.kr/document/{attachments[].path}` | 없음 |
| 게시판별 최신 30건 | `POST api.ksain.net/v1/document.php` (`key`·`boardID`·`count`) | `KSAIN_API_KEY` |
| 전체 목록 | `GET api.ksain.kr/document/list` | 로그인 토큰 — 쓰지 않습니다 |

⚠️ **목록 API 는 최신 30건만 주고 100000번대 글을 빼먹습니다.** 페이지 파라미터도 무시합니다.
그래서 수집은 **번호를 앞으로 훑는 것**이 중심이고, 목록 API 는 새 구 번호를 빨리 알아채는
데만 씁니다.

⚠️ 본문·첨부를 비로그인으로 주는 건 ksain 의 **지금 동작**입니다. 막히면 `KSAIN_TOKEN`
(ksain.kr 로그인 토큰, `POST /auth/signin {uid, password}` 의 `data.token`)을 넣으면 같은
요청에 Bearer 로 붙습니다.

## 수집 (`sync.py`)

```bash
python3.14 -m backend.ksain.sync --backfill   # 처음 한 번 — 두 번호 공간을 처음부터
python3.14 -m backend.ksain.sync              # 주기 실행
```

증분 실행은 셋입니다 — ① 목록 API 로 모르는 구 번호 받기 ② 두 공간 끝에서 빈 번호 30개가
이어질 때까지 앞으로 훑기 ③ 최근 14일 글을 다시 받아 수정(`content_hash`)과 삭제
(`missing_since`) 잡기.

- **빈 번호(`ksain_gaps`)를 기억합니다.** 백필을 다시 돌려도 같은 번호를 또 묻지 않습니다.
  다만 **끝 부근 60개는 매번 다시 묻습니다** — 예약 발행 글은 번호가 먼저 잡히고 나중에 보입니다
- **글마다 커밋합니다.** 한때 50건마다 커밋했더니 그동안 쓰기 잠금을 쥐고 있어서 같은 DB 를
  쓰는 다른 프로세스가 `database is locked` 로 죽었습니다
- 같은 첨부가 목록에 두 번 실려 오는 글이 있습니다(100099). 경로로 중복을 거릅니다
- 사라진 글은 번호(`missing_since`)만 남기고 **제목·본문·첨부 텍스트를 비웁니다.** 분석과 그 글에서
  만든 자동 일정·기억도 지웁니다(`apply.remove_missing`). 개인정보처리방침 4항이 이 동작을 약속합니다 —
  빼면 방침도 고치세요. 다시 확인하는 범위는 최근 14일 글입니다
  - ⚠️ 일정은 **글 번호(`source_ref`)로만** 찾습니다 — 매니저가 고쳐 `manual` 이 된 자동 일정도 글에서 온
    것이라 같이 지웁니다. 한때 `source='ksain'` 만 지워서 고친 일정이 제목·메모째 남았습니다
  - ⚠️ 지워진 글이 하나라도 있으면 **검색 색인을 처음부터** 만듭니다(아래 「검색」) — 고아 토큰이
    `fts5vocab` 으로 읽혀서 지운 글의 낱말이 파일에 남았습니다
- 익명 글은 작성자를 비우고, 원본 응답 사본(`raw`)에서도 `writer` 를 뺍니다 — 한때 `raw` 에는 그대로 남았습니다
- **끝나면 검색 색인을 갱신합니다**(`knowledge.index.refresh`) — 새 글·바뀐 글·새로 읽은 첨부만.
  API 는 ksain.db 를 읽기만 해서 색인은 수집 쪽이 맡습니다. 자세한 건 아래 「검색」

### 첨부

파일은 저장하지 않고 **텍스트만** 남깁니다(원본은 ksain 링크로 엽니다). 시험 명단 xlsx 처럼
개인정보가 든 파일이 섞여서, 서버 디스크에 파일을 쌓아 둘 이유를 만들지 않았습니다.

| 형식 | 읽는 법 |
| --- | --- |
| xlsx | `workbook.py` (표준 라이브러리) — 시트당 150행까지 |
| docx · pptx · hwpx | zip 안의 XML |
| hwp 5.x | `olefile` 로 BodyText 의 문단 레코드(태그 67)만 |
| pdf | `pypdf`, 40쪽까지 |
| 이미지 | 아직 안 읽습니다 (`unsupported`) |

⚠️ **hwp 문단 텍스트의 0~31 은 컨트롤입니다.** 줄바꿈·하이픈 같은 몇 개만 한 글자 폭이고
나머지(표·그림·각주)는 데이터까지 **8글자 폭**을 차지합니다. 한 글자로 보고 건너뛰면
`捤獥汤捯` 같은 깨진 한자가 섞입니다.

⚠️ **코드 단위를 `chr()` 로 한 글자씩 붙이면 서로게이트가 갈라집니다.** 4바이트 글자가 짝 없는
서로게이트 둘로 남고, 저장할 때 UTF-8 인코딩에서 터져 **백필 전체가 죽었습니다.** 지금은
UTF-16 으로 다시 묶어 쌍을 살리고, 모든 추출 텍스트를 저장 전에 한 번 더 거릅니다. 첨부 하나의
저장 실패는 그 첨부만 `error` 로 남깁니다.

```bash
python3.14 -m backend.ksain.sync --attachments-only   # 밀린 첨부만 (백필이 중간에 멈췄을 때)
```

## 분석 (`analyze.py`)

```bash
python3.14 -m backend.ksain.analyze                     # 밀린 글 최신순 150건
python3.14 -m backend.ksain.analyze --minutes 40        # 40분이 지나면 새 글을 더 잡지 않음 (타이머가 씁니다)
python3.14 -m backend.ksain.analyze --post 3092 --dry-run
python3.14 -m backend.ksain.analyze --reapply           # LLM 없이 학사일정·기억만 다시 맞춤
```

글마다 JSON 하나 — `summary` · `importance`(0~3) · `tags` · `mandatory` · `target_grades` ·
`items`(일정: kind·title·`detail`(세부)·날짜·시각·category·대상 학년·대상 전공·`calendar`·`confidence`) ·
`facts`(사실 — 아래 「기억」). `content_hash` 가 바뀐 글은 늘 다시 돌리고, `ANALYZER_VERSION` 을 올렸을
때는 **최근 1년(`REANALYZE_DAYS`)의 글만** 게시판·중요도와 상관없이 다시 돌립니다. v5 부터 사실을 모든
글에서 뽑기 때문입니다(아래 「기억」). 전부 다시 돌리면 데스크탑 GPU 로 하루가 넘습니다.

결과는 글마다 본 DB 에 한 번 커밋합니다 — 자동 일정(`apply.py`)과 기억(`knowledge/facts.py`)을
같은 세션으로 적고(`publish`), 그다음 ksain.db 에 반영 기록(`applied`·`suppressed`)을 남깁니다.

모델 출력은 `coerce()` 가 다시 거릅니다 — 날짜·시각 형식, 허용된 태그·분류, 학년, 전공. 세 학년
전부(`[1,2,3]`)는 학사일정 관례대로 빈 값(전학년)으로 바꿉니다.

**대상 전공**(`target_majors`)은 심화필수 전공 트랙 여섯(수학·정보과학·물리학·지구과학·화학·생물학)으로
적습니다. 학부 공지는 "화학생물학부 주관" 처럼 학부 단위로 오는 일이 많아서 schema 가 학부 이름도 받고,
`coerce()` 가 트랙 둘로 풉니다(`services/majors.py` 의 `normalize` — "화생학부" 같은 줄임말도 받습니다).
여섯 개 전부면 학년과 같은 관례로 빈 값(전공 무관)입니다.

⚠️ **작년 공지를 복사해 연도만 안 고친 글이 있습니다.** 2980번은 2026-08-04 에 올라왔는데
본문 일시가 "2025. 8. 22." 입니다. 작성 시각보다 200일 넘게 과거인 날짜는 작성 연도로
옮겨 봅니다(`_fix_year`).

⚠️ **JSON schema 에 `["string", "null"]` 유니언을 쓰지 마세요.** Ollama 의 문법 제약이 그
칸을 null 로만 채워서 본문에 `09:00 ~09:20` 이 있어도 시각이 비었습니다. 문자열 하나로 두고
없으면 빈 문자열을 받습니다.

⚠️ **모델은 글에 없는 날짜를 지어냅니다.** 3092번(기말고사 시간표 안내)은 날짜가 첨부 xlsx 에만
있는데, 첨부를 못 본 상태에서 "11/1 기말고사" 를 만들었고 PDF 일정과 날짜가 안 겹쳐 중복
거르기도 통과했습니다. 그래서 세 겹으로 막습니다.

1. **근거 검사** (`grounded`) — 항목 날짜가 `12.11`·`12/11`·`12월 11일`·`2026-12-11` 꼴로 제목·
   본문·첨부 어딘가에 있어야 학사일정에 들어갑니다. 없으면 정보로만 남습니다
2. **시트별 발췌** — xlsx 첨부는 앞에서부터 자르지 않고 시트마다 고르게 나눠 프롬프트에 넣습니다.
   3092 는 첫 시트가 명단 머리라 날짜가 든 둘째 시트가 통째로 안 보였습니다
3. 요약에도 "본문·첨부에 없는 날짜는 쓰지 말고 '첨부 참고'" 를 지시합니다

**첨부를 아직 못 읽은 글은 분석을 미룹니다.** 첨부 텍스트는 `content_hash` 에 안 들어가서, 첨부
없이 한 번 분석되면 첨부를 읽은 뒤에도 다시 돌지 않습니다.

⚠️ **Ollama 기본 컨텍스트는 4096 토큰이고, 넘치면 프롬프트 앞부분(시스템 지시문)을 조용히
자릅니다.** 본문 5천 자 + 첨부 6천 자면 넘칩니다. 게이트웨이가 Ollama 를
`OLLAMA_CONTEXT_LENGTH=16384` 로 띄웁니다(`deploy/llm-gateway/gateway.py`).

⚠️ **사실까지 뽑으면서 글 하나가 15~30초 걸립니다**(v3 까지는 5~10초 — 출력 JSON 이 길어졌습니다).
타이머 유닛은 50분(`TimeoutStartSec`)이 지나면 작업을 죽이므로 `--minutes 40` 으로 시간에서 끊습니다.
글마다 커밋하니 다음 주기가 이어 받습니다. 버전을 올린 직후에는 밀린 글(2026-10 기준 최근 1년 약 710건)을
최신순으로 네다섯 시간에 걸쳐 따라잡습니다.

## 학사일정 자동 관리 (`apply.py`)

| 반영 | 건너뜀 |
| --- | --- |
| `calendar=true`, `confidence ≥ 0.6` | 끝나는 날이 14일보다 더 지난 항목 (백필한 옛 글) |
| 기간 45일 이하 | 날짜가 겹치고 제목이 비슷한 공용 일정이 이미 있음 (PDF·다른 글) |
| 날짜가 글에 적혀 있음 (`grounded`) | 날짜가 겹치고 핵심어(귀가·귀교·폐쇄·기말고사…)를 공유 — "12월 귀가" = "귀가(전학년)". **분류는 안 봅니다** — 모델이 기말고사를 `academic` 으로 줘서 PDF 의 `exam` 일정과 겹쳐 들어갔습니다 |
| | 시험 분류인데 같은 기간에 PDF 시험 일정이 있음 |
| | **사람이 지웠거나 고친 일정** |

위 두 "비슷한 일정" 규칙은 **대상 학년이나 전공이 서로 겹치지 않으면 걸지 않습니다**(`_apart`). "1학년 귀가"
와 "2학년 귀가", 학부마다 따로 여는 "학부 설명회" 는 이름이 같아도 다른 일정입니다. 대상이 비어 있으면
전체라서 늘 겹칩니다.

마감(`deadline`)은 종일 일정으로 넣고 제목에 시각을 붙입니다(`… (15:00까지)`). 시간 블록으로
그리면 15:00–16:00 행사처럼 읽힙니다.

글이 바뀌면 **그 글 것만**(`source_ref LIKE '<번호>:%'`) 지우고 다시 만듭니다.

- **사람이 고친 일정은 자동 관리에서 빠집니다.** `PUT /calendar/events/{id}` 가
  `source='ksain'` 을 `manual` 로 바꿉니다 — 다음 분석이 고친 내용을 덮어쓰지 않게요
- **사람이 지운 일정은 다시 만들지 않습니다.** 반영 기록(`Analysis.applied`)에 있던 일정이
  없어졌으면 그 항목의 서명(날짜|제목)을 `suppressed` 에 넣습니다
- ⚠️ **`holiday`·`term` 분류는 쓰지 않습니다.** 홈이 `holiday` 일정으로 그날 수업을 지우고,
  `term` 의 개학·종업 표지로 방학을 판정합니다. 모델 실수 하나로 전교생 시간표가 사라집니다
- 일정 `note` 맨 앞에 항목의 세부(`detail` — 장소·버스 시각·준비물)가, 그 뒤에 원문 링크
  (`https://ksain.kr/document/{id}`)가 들어갑니다. 날짜가 든 정보는 기억에 남기지 않으니(아래 「기억」)
  그 일정에 딸린 내용은 여기가 유일한 자리입니다. Ask 의 `calendar` 도구도 이 메모를 그대로 봅니다
- 대상 전공(`target_majors`)도 항목에서 그대로 옮깁니다 — 화면의 "내 학년·전공" 거르기와 Ask 의 `mine` 이 씁니다.
  그래서 v5 부터는 학부·전공 단위 행사와 마감(학부 설명회·모의면접)도 `calendar=true` 로 올리게 지시합니다.
  거를 수단이 생겨서, 일부 학생 대상 일정이 모두의 달력을 덮지 않습니다

⚠️ **`--reapply` 는 `applied` 를 비우고 시작합니다.** 분석을 다른 DB(스테이징)에서 돌렸으면
그 기록은 다른 DB 의 일정 번호라, 남겨 두면 "사람이 지운 일정" 으로 읽혀 전부 막힙니다.
스테이징 사본에서 일정을 지워 본 적이 있으면 그 기억(`suppressed`)도 운영에 따라오므로, **첫
운영 반영은 `--reapply --fresh`** 로 둘 다 비웁니다.

## 검색 (`knowledge/index.py` · `knowledge/search.py`)

```bash
python3.14 -m backend.knowledge.index            # 바뀐 글만 (수집이 끝날 때마다 자동으로 돕니다)
python3.14 -m backend.knowledge.index --rebuild  # 처음부터 — 글 2,400건·조각 2만 7천 개에 5초 남짓
```

**한국어는 두 글자씩 겹쳐 자른 바이그램으로 색인합니다**(`knowledge/text.py`). "필참교육" →
`필참 참교 교육`. 한때 FTS5 를 안 쓰고 LIKE 로 찾았는데, FTS5 의 trigram 토크나이저가 "필참"·"귀가"
같은 **두 글자 단어를 못 찾아서**였습니다. 바이그램을 띄어 쓴 문자열을 `unicode61` 토크나이저에
그대로 넣으면 두 글자 단어도 찾고, 검색어의 바이그램을 이은 **구문**(`"기말 말고 고사"`)으로 찾으면
그 글자열이 그대로 든 곳만 걸립니다. 한글 사이의 공백은 지우고 자르므로 "수강 신청" 과 "수강신청" 이
같은 말입니다.

- ⚠️ 토크나이저는 `unicode61 remove_diacritics 0` 입니다. 기본값은 한글 음절을 자모로 풀 수 있습니다
- **글자는 저장하지 않습니다.** FTS 표는 contentless 이고 조각 표(`ksain_search_chunks`)는 원문의
  위치(`start`·`stop`)만 듭니다 — 색인이 19MB, ksain.db 는 35 → 57MB 입니다
- ⚠️ **contentless FTS5 는 행을 못 지웁니다**(3.43 부터 되는데 서버가 3.37). 글이 바뀌면 조각 행만
  지우고 토큰은 고아로 남깁니다 — 검색이 조각 표와 이어 붙여 보므로 안 걸립니다. 고아가 조각의 30% 를
  넘으면 처음부터 다시 만듭니다. 조각 id 를 재사용하면 고아 토큰이 새 조각에 붙어서 `AUTOINCREMENT` 입니다.
  ⚠️ 단 **원문에서 지워진 글이 생기면 바로 처음부터** 만듭니다(1~2초) — 고아 토큰은 `fts5vocab` 으로 읽혀서
  "지웠다" 가 안 됩니다
- 글마다 지문(`ksain_search_stamps` — 본문 해시 + 첨부 상태·길이)을 둬서 **바뀐 글만** 다시 색인합니다.
  자르는 법이 바뀌면 `INDEX_VERSION` 을 올리세요 — 다음 수집이 처음부터 다시 만듭니다
- **색인은 수집 쪽(`baeks`)만 씁니다.** API 는 읽기만 하고, 색인이 아직 없으면(새 코드로 수집이 한
  번도 안 돌았으면) 후보를 LIKE 로 뽑아 같은 점수로 매깁니다

검색은 두 단계입니다. FTS5 가 질문 낱말이 든 조각을 BM25 순으로 넉넉히(300개) 뽑고, 글 단위로 다시
매깁니다.

| 점수 | 값 |
| --- | --- |
| 낱말이 제목에 / 분석 요약에 / 본문에 / 첨부에 | 5 / 3 / 1 / 1 × 낱말 무게 |
| 질문 낱말을 얼마나 덮었나 (무게 합 비율 = 관련도) | 최대 +4 |
| BM25 (가장 잘 맞는 조각, 1등 글 기준 비율) | 최대 +3 |
| 중요도 · 일정이 아직 안 지났는가 · 최신성 | ×0.5 · ±2 · 오늘 +4 → 180일 0 — **관련도를 곱해서** |

- **낱말 무게는 희소도(IDF)입니다.** "외출 신청 방법" 에서 "신청"(조각 3,634개)·"방법"(2,108개)은
  흔하고 "외출"(221개)은 드뭅니다. 같은 무게로 셌더니 "HP 참가 신청" 같은 최근 공지가 외출 안내를 이겼습니다
- **최신성과 "아직 안 지났는가" 는 관련도를 곱합니다.** 이게 없으면 제목에 "포스터" 가 든 8월 중간발표
  공지가 11월 최종발표 공지를 이겨서 "R&E 포스터 언제까지?" 에 지난 마감을 답했고, 그렇다고 그대로 더하면
  질문과 상관없는 이번 주 공지가 앞에 섭니다
- **질문 말은 검색어가 아닙니다** — 조사("마감일이")·용언 꼬리("외출하려면" → "외출")를 떼고, "언제"·
  "이번"·"내야" 같은 말은 뺍니다. 기간은 검색어가 아니라 `since`·`until` 로 넘깁니다
- **글마다 근거 발췌(`passages`)를 싣습니다** — 본문이든 첨부든 질문 낱말을 가장 무겁게 덮은 조각에서,
  드문 낱말이 모인 자리를 중심으로 420자. 12B 모델은 첨부 이름을 보고도 `read_ksain` 을 잘 안 부르는데,
  마감일 같은 답이 첨부에만 있는 공지가 많습니다(100109 의 PDF "최종보고서 11월 29일"). ⚠️ 발췌 후보는
  상위 글 안에서 **다시** 뽑습니다 — 전체 상위 300조각은 흔한 낱말 조각으로 차서 정작 답이 든 조각이
  빠졌습니다

## 기억 (`knowledge/facts.py` · 본 DB `facts`)

분석기(v5)가 **모든 글에서** 사실을 최대 6개 뽑습니다 — 방법·장소·대상·준비물·양식·기준·규칙·바뀐 점·
결과처럼 **날짜 없이도 맞는** 정보입니다. 글을 안 읽은 사람이 봐도 뜻이 통하는 한 문장(`statement`)과
주제(`topic`), 쓸모가 끝나는 날(`valid_until`, 규칙이면 비움), 대상 학년·전공, 확신도가 붙고, 출처 게시판을
말머리까지(`board` — "공지사항 · 교무연구부", "규정 게시판 · 폐지") 같이 적습니다(ksain `Post.board_label`).
Ask 가 질문에 맞는 것을 골라 시스템 프롬프트에 싣습니다([agent.guide.md](agent.guide.md)).

**날짜는 학사일정이 맡습니다.** v4 는 "R&E 최종보고서는 11월 29일까지 제출" 같은 사실을 그대로 남겼는데,
기억은 질문마다 프롬프트에 실려서 마감이 연장되거나 매니저가 학사일정을 고쳐도 옛 날짜가 계속 나갑니다.
그래서 날짜가 든 정보는 일정 항목(items)으로만 보내고, 그 일정에 딸린 세부는 항목의 `detail` 에 적게
합니다(→ 자동 일정의 메모). 지시를 어기고 날짜를 단 사실은 아래처럼 코드가 한 번 더 거릅니다.

**중요도로 거르지 않습니다**(v4 는 중요도 0 인 글의 사실을 버렸습니다). 감사 글·동아리 홍보에도 물어볼
거리가 있고, 기억 줄에 게시판이 같이 실려서 모델이 교무연구부 공지와 홍보 글을 가려 읽습니다. 다른
학생이 물어볼 정보가 없는 글이면 빈 배열을 내라고 지시합니다.

**글에 묶인 요약 DB 입니다.** 사실마다 출처 글이 있고, 손으로 지어 넣는 사실은 없습니다. 글이 바뀌면 그
글의 사실만 다시 적고, 글이 ksain 에서 지워지면 같이 지웁니다(개인정보처리방침 4항).

`coerce_facts()` 가 거르는 것:

- ⚠️ **날짜가 든 문장은 기억에 남기지 않습니다**(`_DATED`) — "11월 29일"·"11월 귀가"·"2026. 11. 29."·
  "11/13"·"(금)". 뺀 문장은 버리지 않고, 문장에 적힌 날짜가 시작일이나 끝날인 일정 항목을 찾아 그 `detail`
  뒤에 붙입니다(`_attach_dated`) — 모델이 "귀가일(11/13) 학교버스는 16:40, 17:30 운행" 을 사실로 써서,
  그냥 버리면 버스 시각이 어디에도 안 남았습니다. 맞는 일정이 없으면 버립니다
- ⚠️ **"3.5"·"1.5배"·"1/3 이상"·"A-(3.7)" 은 날짜가 아닙니다.** 평점·결석 비율 같은 기준이 기억의
  단골이라, 숫자 둘은 연도·끝 마침표·요일·괄호·"까지" 가 붙거나 두 자리 수가 든 슬래시("11/13")일 때만
  날짜로 봅니다. 소수는 괄호를 봐 주지 않습니다
- 학번 꼴(`25-059`)·졸업생 표기("배준수(KSA18)")·**학생 이름**이 든 문장은 버리고(`_personal`), 전화번호·
  이메일은 문장에서 걷어냅니다(뒤에 붙은 조사는 앞말에 붙여 "이메일 로" 가 남지 않게)
- ⚠️ **학생 이름은 지시문만으로 안 막힙니다.** 모든 글에서 뽑으면서 이름이 섞일 자리가 늘었고(2026-10 사본에서
  최근 1년 글 710건 중 159건에 학생 이름 — 연구회 홍보·선발·선거 게시판 순), 모델은 "이우주 학생이
  선발되었습니다" 처럼 지시를 어기고 이름을 씁니다. 그래서 본 DB 학생 명단의 **세 글자 이상** 한글 이름으로 한 번
  더 거릅니다(`student_names` — 두 글자 이름은 "이수"·"정보" 같은 낱말과 겹칩니다). 교사 이름은 거르지 않습니다 —
  시간표에 이미 나오고, "문의는 ○○○ 선생님께" 는 쓸모 있는 사실입니다. 일정 세부(`detail`)도 같은 판정으로
  이름이 든 문장만 뺍니다
- 확신도 0.6 미만은 옮겨 적지 않습니다

**사람의 손이 우선입니다.** 매니저가 Admin 의 기억 패널(`/facts`)에서 숨긴 사실(`status='hidden'`)과
고친 사실(`edited`)은 글을 다시 분석해도 그대로 두고, 새로 뽑힌 사실이 그것과 같은 말이면(`similar` —
바이그램 절반 이상 겹침) 다시 만들지 않습니다. 자동 일정이 사람이 지우거나 고친 것을 되살리지 않는 것과
같은 규칙입니다.

⚠️ **기억이 본 DB 에 있는 이유**는 사람이 고치는 결과물이라서입니다. 서버에서 API 가 쓸 수 있는 DB 는 본
DB 뿐이라, ksain.db 에 두면 패널에서 숨기기·고치기가 운영에서 막힙니다. 대신 **본 DB 백업에는 기억과 자동
일정을 넣지 않습니다** — 백업은 1년을 두어서, 넣으면 원문이 지워져도 백업 속에 그만큼 남습니다
([core/db.guide.md](core/db.guide.md)). 검색은 `facts_fts`(바이그램 토큰을
같이 저장하는 보통 FTS5 표)로 하고, `knowledge/facts.py` 가 사실을 쓰거나 고칠 때 같이 맞춥니다 — 다른
곳에서 `facts` 를 직접 고치면 검색이 옛 문장으로 걸립니다.

색인에는 주제·문장 말고 **대상 전공과 그 학부 이름**도 넣습니다(`_searchable`). 학부 공지의 사실은 문장에
학부 이름이 없는 일이 많아서("면접 특강 참석 시 자기 계발 점수 부여"), 이게 없으면 "화학생물학부 면접 특강"
으로 물었을 때 안 걸립니다. 질문자와 다른 학년·전공 대상인 사실은 빼지 않고 순위만 내립니다(`find` 의
`grade`·`major`) — 다른 학년·전공 것을 묻기도 합니다.
