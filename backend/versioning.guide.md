# backend/versioning.py Guide

> [← Backend Guide](CLAUDE.md)

## 역할
데이터 회차 — 수집이 한 학기를 갈아 끼운 이력. **회차 조건을 아는 유일한 자리**입니다.

## 왜 만들었나

재수집은 한 학기를 통째로 갈아 끼우는 작업이었습니다. 그래서 "지난주엔 뭐가 달랐나"를
물으면 백업 파일을 열어 보는 수밖에 없었는데, 파일 이름의 날짜는 **백업을 뜬 날짜지
데이터가 바뀐 날짜가 아니라** 그것마저 어긋났습니다. 실제로 서버에 8월 11일부터 19일까지
내용이 완전히 같은 백업 다섯 개가 쌓여 있었습니다.

행마다 유효 구간을 달아 두면 변경분만 쌓입니다. 실측으로 회차당 몇 KB 수준이고, 학기가
새로 열릴 때만 150KB 정도 붙습니다.

## 읽기

```python
from backend.versioning import at_version

db.query(models.Class).filter(at_version(models.Class))       # 지금 유효한 것
db.query(models.Class).filter(at_version(models.Class, 5))    # 5회차 시점
```

구간은 시작을 포함하고 끝을 포함하지 않습니다 — 5회차에 닫힌 행은 4회차까지 유효합니다.

⚠️ **조건을 손으로 적지 마세요.** 언젠가 한 자리를 빠뜨리고, 그러면 폐강된 분반이 조회에
섞여 나옵니다. 화면에서 티가 안 나는 종류의 사고입니다.

**현재를 물을 때는 학기를 몰라도 됩니다** — 열려 있는 행은 어느 학기든 `version_to` 가
비어 있으니까요. 학기를 알아야 하는 건 과거를 물을 때뿐이라, 대부분의 조회 자리는 인자
없이 부르면 끝납니다.

관계(`Class.times` 등)는 `models.py` 에서 이미 막혀 있어 조건이 필요 없습니다. 대신
**과거 회차는 관계로 못 읽습니다** — `classes_router` 의 `roster`/`slots` 처럼 직접
물어야 합니다.

## 함수

| 함수 | 하는 일 |
|------|---------|
| `at_version(model, version=None)` | 유효 구간 조건. 인자가 없으면 지금 |
| `current_version(db, year, semester)` | 그 학기의 최신 회차. 없으면 `0` |
| `version_map(db)` | `{"2026-2": 7}` — `/auth/me` 가 실어 보내는 값 |
| `record_version(db, ...)` | 회차 기록. **바뀌었는지는 판단하지 않습니다** |
| `terms_of_student` · `terms_of_teacher` | 이름을 고치면 어느 학기 캐시가 갈려야 하는지 |
| `bump_terms(db, terms, note)` | 수집이 아닌 변경으로 회차만 올립니다 |

## 올리는 규칙

**바뀐 게 있을 때만** 늘어납니다. 수집을 돌려도 결과가 직전과 같으면 회차도 백업도 만들지
않습니다 (`parser_run.diff_terms`).

화면에 나가는 내용이 달라지는 변경이면 수집이 아니어도 올립니다 — 학생·교사 이름 수정이
그렇습니다. 회차가 그대로면 브라우저가 캐시를 계속 쓰기 때문입니다. 다만 `students`·
`subjects` 에는 버전 구간이 없어서 **과거 회차를 열어도 이름은 현재 값으로 보입니다.**
캐시는 정확히 갈리고, 이름 이력만 없는 절충입니다.

## 승격

**자동입니다.** 수집이 성공하면 곧바로 학생들에게 나갑니다. 사람이 확인하고 올리는 절차는
두지 않았습니다 — 매번 손이 가는 대신 얻는 것이 KEIS 가 이상한 값을 준 드문 경우뿐이고,
그때는 백업에서 되돌리면 됩니다.
